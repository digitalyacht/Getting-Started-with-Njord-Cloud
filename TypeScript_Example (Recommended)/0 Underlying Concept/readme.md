# Viam Machine Monitoring and Hardware Interface

## Overview

This project demonstrates how to communicate with a robot running on the [Viam platform](https://www.viam.com/) using the Viam TypeScript SDK. It connects to a remote machine, discovers its available resources, and retrieves information from several hardware and software components.

The main purpose of the code is to provide a centralised interface for monitoring machine health, retrieving boat or system data, accessing hardware interfaces, and interacting with supporting services.

## Underlying Concepts

### 1. Viam Robot Client and Authentication

The project uses `@viamrobotics/sdk` to establish a connection with a remote Viam machine.

```typescript
const machine = await VIAM.createRobotClient({
    host,
    credentials: {
        type: 'api-key',
        payload: '<API-KEY>',
        authEntity: '<API-KEY-ID>',
    },
    signalingAddress: 'https://app.viam.com:443',
});
```

The robot client acts as the primary communication interface between the application and the remote machine.

It handles:
- Authentication using an API key and API key ID.
- Establishing a connection to the remote machine.
- Accessing registered hardware components and services.
- Sending requests and receiving sensor data.

#### Please note: You are able to handle connections in other ways than just API keys. [OAuth with VIAM & Fusion Auth](https://docs.viam.com/organization/oauth/)

### 2. Resource Discovery

```typescript
console.log(await machine.resourceNames());
```

Viam uses a resource-based architecture. Hardware components and software services are exposed as resources that can be accessed through their respective client interfaces.

The `resourceNames()` method retrieves the resources registered with the machine.

This allows the application to discover available functionality without needing to interact directly with the underlying hardware.

### 3. PGN Data Collection (`all-pgn`)

The `all-pgn` module is one of the most useful components in this implementation.

```typescript
const allPgnClient = new VIAM.SensorClient(machine, 'all-pgn');
const readings = await allPgnClient.getReadings();
```

Parameter Group Number (PGN) is a concept associated with the NMEA2000 boat communication protocol.

NMEA2000 uses PGNs to identify groups of related boat data transmitted over a CAN (Controller Area Network) bus.

Depending on the underlying implementation, PGN data can provide access to information such as:
- Engine operating parameters.
- boat speed and operating conditions.
- Temperature and pressure measurements.
- Diagnostic and fault information.
- Other boat-specific telemetry.

The `all-pgn` resource provides a convenient interface for retrieving the available PGN-related readings in one request.

This makes it particularly valuable for boat monitoring, telemetry collection, diagnostics, and integration with external data processing systems.

*Note: The precise PGN fields and their meanings depend on the implementation of the underlying Viam resource.*

### 4. Hardware and System Monitoring (HWM)

The HWM modules provide access to important machine health and performance information.

The code accesses three separate monitoring resources:

| Module | Purpose |
|---|---|
| `hwm-temps` | Retrieves temperature readings and thermal information. |
| `hwm-memory` | Retrieves memory utilisation and system memory information. |
| `hwm-disk` | Retrieves disk utilisation and storage information. |

Each module is accessed through a Viam `SensorClient`:

```typescript
const hwmTempsClient = new VIAM.SensorClient(machine, 'hwm-temps');
const readings = await hwmTempsClient.getReadings();
```

The `getReadings()` method provides a standardised way to retrieve sensor information.

These modules are particularly useful for monitoring the operational health of the machine, identifying potential resource constraints, and detecting conditions that could affect system reliability.

### 5. Event Management

```typescript
const eventManagerClient = new VIAM.SensorClient(machine, 'event-manager');
const events = await eventManagerClient.getReadings();
```

The `event-manager` resource provides access to event-related readings.

An event-management component can be used to expose system events, status changes, or other information generated by the machine.

This can be useful for:
- Monitoring system state changes.
- Identifying operational events.
- Supporting fault detection.

The exact event structure depends on the resource implementation.

## Key Modules and Their Importance

The most useful modules in this implementation are **`all-pgn` and the HWM modules**.

| Priority | Module | Why it is useful |
|---|---|---|
| 1 | `all-pgn` | Provides access to boat-related PGN data, potentially exposing a broad range of operational and diagnostic information. |
| 2 | `hwm-temps` | Allows monitoring of system temperatures and thermal conditions. |
| 3 | `hwm-memory` | Provides visibility into memory utilisation and available system resources. |
| 4 | `hwm-disk` | Helps monitor storage capacity and disk utilisation. |

Together, these modules provide two important perspectives:

- **boat-level monitoring:** `all-pgn` provides access to boat telemetry and diagnostic information.
- **Machine-level monitoring:** The HWM modules provide insight into the underlying computer's hardware health and resource utilisation.

Combining these data sources makes it possible to build a more comprehensive monitoring solution.

## Error Handling

The application uses a top-level error handler:

```typescript
main().catch((error: unknown) => {
    console.error('encountered an error:', error);
});
```

This ensures that errors occurring during asynchronous execution are caught and logged rather than becoming unhandled promise rejections.

## Summary

This implementation provides a starting point for a remote machine monitoring and data acquisition system using the Viam SDK.

Its main capabilities include:

1. Connecting securely to a remote Viam machine.
2. Discovering registered machine resources.
3. Collecting boat-related PGN information through `all-pgn`.
4. Monitoring hardware health through the HWM temperature, memory, and disk modules.
5. Retrieving event-related readings.

**The most valuable starting points for further development are `all-pgn` and the HWM modules.** Together, they provide a useful foundation for understanding both the operational state of the boat and the health of the computer running the system.

These modules could form the basis of a wider telemetry platform, supporting real-time monitoring, historical data analysis, fault detection, and remote diagnostics.
